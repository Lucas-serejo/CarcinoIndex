# Experimental persistence foundation

This layer is independent of `SAM2Segmenter` and is used by the attempts route.
The stateless route remains independent of the database. No inference or write is
triggered by importing the modules. The [SAM 2.1](sam2_inference_contract.md)
contract remains valid for the current API.

## Persistence model

| Entity | Content and relationships |
| --- | --- |
| ClinicalCase | UUID, legacy field `anonymous_patient_code` and creation time; supports multiple images. In the planned Experiment B, the field holds a pseudonymous code of the experimental case, without establishing patient identity. Uniqueness is not required. |
| Image | UUID, case FK, relative path, positive width/height, hexadecimal SHA-256 of the original bytes and creation time. Indexed hash, with no automatic deduplication across cases. |
| Evaluation | UUID, image FK, PCI region 0–12 or NULL when undetermined, annotator code, manual clinical LS 0–3 or NULL (undetermined when finalized), optional annotator_confidence 0–1 (only with LS), reviewed_attempt_id UUID and segmentation_quality string (optional while draft), status and timestamps. Allows independent evaluations of the same image. |
| SegmentationAttempt | UUID, evaluation FK, positive sequence number unique within that evaluation, box/points prompt, prompt JSONB, mask path, SAM metadata JSONB and creation time. |

IDs are generated by the application; creation timestamps are generated by the
database with time zone. FKs restrict deleting parents that have dependents.
There are no blobs. `annotator_confidence` is the confidence declared by the
annotator, never SAM's `selected_score`. Prompts and metadata must be
JSON-serializable objects; the caller supplies a validated prompt and
`result.to_metadata_dict()`, including the `multimask_output` setting in the
prompt for reproducibility. Do not include mask arrays or logits in the JSON.

The repository creates evaluations as `draft`. Finalizing records `finalized_at`
and the explicitly supplied LS, an integer from 0 to 3 or NULL when undetermined,
plus `reviewed_attempt_id` and `segmentation_quality`. Under the same evaluation
lock, the repository checks that the attempt exists and belongs to the
evaluation. Both fields are written in the same short transaction, with no
circular ORM relationship or new table. Ownership is enforced by the repository;
the UUID does not introduce a circular FK. While `draft`, LS may be `None`; when
`finalized`, `None` means undetermined. The database and the API reject
confidence supplied without LS. Additional attempts and a second finalization are
refused by the repository. It locks the evaluation row until commit/rollback,
together with database uniqueness, to serialize numbering and finalization.
These immutability rules belong to the repository; they are not triggers against
direct SQL. JSONB must be replaced as a whole on updates, not modified in place.

`finalized` records that the evaluation was closed; it does not automatically
indicate a validated mask. The reviewed attempt is tied to the human judgment
`adequate` / `partially_adequate` / `inadequate`, without acceptance or
transformation into a reference/ground truth. PCI region and LS are supplied by
the specialist when determinable; neither is inferred by SAM. The workflow does
not calculate the complete PCI. Features are not implemented. Image/mask export
is not implemented; there is a read-only CSV export of finalized evaluations,
described in the [backend README](../../backend/README.md).

## Using the foundation

After `python -m alembic upgrade head`, a script can persist already validated
bytes and metadata. Example with a synthetic image (no clinical image):

```python
from io import BytesIO
from PIL import Image as PILImage
from backend.app.persistence.database import (
    PersistenceSettings, create_database_engine, create_session_factory,
)
from backend.app.persistence.repository import ExperimentRepository
from backend.app.storage.local import LocalStorage

settings = PersistenceSettings.from_env()
engine = create_database_engine(settings)
sessions = create_session_factory(engine)
storage = LocalStorage(settings.storage_root)
buffer = BytesIO()
PILImage.new("RGB", (32, 24)).save(buffer, format="PNG")
stored = storage.save(buffer.getvalue(), category="images", suffix=".png")
try:
    with sessions.begin() as session:
        repo = ExperimentRepository(session)
        case = repo.create_case("synthetic-case")
        image = repo.add_image(
            case_id=case.id,
            storage_path=stored.path, width=32, height=24, sha256=stored.sha256,
        )
        evaluation = repo.create_evaluation(
            image_id=image.id, pci_region_id=0, annotator_code="expert-001",
        )
except Exception:
    storage.delete(stored.path)
    raise
finally:
    engine.dispose()
```

`add_attempt()` receives the evaluation UUID, the prompt type and data, the path
of the previously saved PNG mask and the SAM metadata. `list_attempts()` returns
the attempts in order; `get_evaluation()` retrieves the evaluation and its
relationships. `finalize_evaluation()` records the manual LS or NULL and requires
the qualitative review tied to the attempt. The repository flushes, but only the
caller decides the complete transaction.

Storage generates UUID names independent of the original name and checks that
resolved paths stay inside the root, refusing traversal, absolute paths and
unexpected extensions. It neither validates nor transforms pixels; that is the
caller's job. The root must be controlled by the application, without concurrent
symlink changes by other users. Original names are not persisted, as they may
contain identifiable information. Use only properly anonymized files and codes in
the experiment.

Database and filesystem have no joint transaction. Saving before the commit
avoids publishing a record before the write completes; on known failures the
caller must remove newly created files. Process interruption can leave orphans;
a connection failure during commit can leave an uncertain outcome, which requires
checking the record before removing files. There is no automatic orphan collector
at this stage. Backups must include both the database and the storage.

## Migrations and validation

`0001_experiment` creates the four tables, FKs, indexes and checks and remains
unchanged. `0002_segmentation_review` adds the two nullable fields to Evaluation.
Checks restrict quality to the three categories and require both fields to be
null or both to be filled. Old evaluations finalized without a review remain
valid; only new finalizations through the API require the review. Downgrading to
`0001_experiment` removes only the review fields and their checks, losing that
review data. `0003_optional_clinical_context` makes the region nullable, removes
the check requiring LS when finalized, and adds the confidence-only-with-LS
check. It does no backfill and creates no sentinels. Its downgrade restores the
previous contract: records with a NULL region or finalized with NULL LS must be
removed explicitly before reverting; the migration neither deletes data nor
invents values. `python -m alembic downgrade base` removes these tables and their
records; use it only for deliberate rollback on a disposable database. Files
remain in storage. Migrations do not import the SAM model or require a
checkpoint/CUDA.

Local tests cover configuration, offline SQL and storage. PostgreSQL tests cover
real persistence, JSONB, integrity, rollback, concurrency, migration-model
correspondence and the upgrade/downgrade cycle.

Technical references: [SQLAlchemy 2.x transactions](https://docs.sqlalchemy.org/en/20/orm/session_transaction.html)
and [Alembic configuration](https://alembic.sqlalchemy.org/en/latest/tutorial.html).

## HTTP integration of attempts

`POST /api/v1/evaluations/{evaluation_id}/segmentations` looks up an existing
evaluation, requires `draft` and obtains the PCI region and the storage_path of
the related image. The read transaction ends before inference. The LocalStorage
bytes go through the same JPEG/PNG decoder as uploads, producing RGB uint8
without resizing or orientation transformation.

The prompt parser is shared with the stateless API. The attempt stores
`box_xyxy` or `points_xy` + `labels`, always with `multimask_output`. The
metadata are those produced by SAM, without embedding the image, mask or logits
in the JSONB. The PNG is saved in `masks/`, and `add_attempt()` revalidates the
draft with its existing lock and assigns the next sequence number. The commit
happens before the 201 response. If the transaction fails, the API tries to
delete only the newly created PNG. A failure in that deletion returns a generic
error and may leave an orphan. Process interruption and a lost commit
confirmation remain limitations: in the latter case, the cleanup may remove a
file whose record was committed; manual reconciliation is required. There are no
retries or distributed coordination.

The response carries IDs, sequence number, region (NULL when undetermined),
metadata and a Base64 PNG, without local paths. The evaluation remains draft and
its clinical fields are not changed. HTTP tests use a fake SAM; the PostgreSQL
tests share the isolated-schema fixture in `tests/app/conftest.py` and are run by
the current workflow.
